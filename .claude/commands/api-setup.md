1. **Manager account (MCC).** Check if I have one; if not: ads.google.com/home/tools/manager-accounts - create it (free), then link my regular Ads account to it.

Coach me through the form using it:

To find the number: Cloud Console → click the project picker at the top → the "ID" column shows the project *ID*, but you need the NUMBER - open the project's **Dashboard** (or ☰ → Cloud overview → Dashboard) and copy "Project number" from the Project info card. It's all digits; if what you copied has letters, that's the project ID, wrong field.

4. **OAuth credentials.** In the SAME Google Cloud project whose number went on the application (one project per developer token) → enable Google Ads API → OAuth consent screen: **External, and PUBLISH it to "In production"**. Never leave it in Testing - a Testing-mode refresh token dies after 7 days, which is Google's number one cause of `invalid_grant` and the "it worked last week" support ticket. Create an OAuth Client ID (Desktop app). Save client ID + secret into `.env`.
5. **Refresh token.** Run `python3 code/get_refresh_token.py` and paste the resulting token into `.env`. Fill `GOOGLE_ADS_LOGIN_CUSTOMER_ID` (the MCC ID) and `GOOGLE_ADS_CUSTOMER_ID` (my account ID) - both 10 digits, no dashes. Python 3.10 or newer (3.9 loses access at the v22 sunset, October 2026).
6. **Verify:** `python3 code/test_connection.py`. Green = the machine layer is live on Explorer. Any error → the error list in the reference names the fix (`DEVELOPER_TOKEN_INVALID` usually means the token was copied from the wrong account or 2SV/passkey isn't in place; `invalid_grant` means Testing mode or a revoked token).
