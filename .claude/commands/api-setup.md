1. **Google Cloud project - the thing access now lives on.** console.cloud.google.com → project picker at the top → **New Project** → name it `google-ads-dashboard` → **Create** → wait ten seconds and make sure it is selected in the picker. Then enable the API: https://console.cloud.google.com/flows/enableapi?apiid=googleads.googleapis.com → **Enable**. Enabling it grants the project **Test access** automatically (test accounts only - step 2 lifts it). Two rules:
   - **One clean project for this repo.** Never one an agency or another tool has used - the access level, the OAuth client and the brand verification all sit on it, so a reused project carries someone else's level and someone else's verification.
   - **Billing off, or a paid account - never the Free Trial.** A project on the Google Cloud Free Trial, or with a suspended billing account, gets its Explorer and Basic applications rejected even after brand verification passes (Google's open known issue, checked 16 September 2026). Either leave billing off or upgrade the project to a paid tier.
   Record the project name in CLAUDE.md "## My setup".

2. **Explorer access - production reads and writes, today.** Open the Google Ads API Overview page: https://console.cloud.google.com/google/ads-apis/overview (or type "Google Ads API" in the top search bar → open it → **Manage** → **Manage access level**). Current access level reads **Test**. Expand **Upgrade access level** → Next access level: **Explorer** → **Apply for access**. Whatever the application asks, answer as what you are: an advertiser managing your own account with your own tooling - company type Advertiser, and the paste-ready intended-use paragraph is in the reference, Step 2. Google reviews it automatically and the page flips to Explorer, usually straight away. Explorer runs every command in this repo except the Keyword Planner volume pull in `/keywords` (2,880 operations a day, no planning services) - that is what Basic unlocks in step 4. Record "Explorer, [date]" in "## My setup".

3. **OAuth consent screen and brand verification - the gate to Basic.** Same project → ☰ → **APIs & Services** → **OAuth consent screen** (Google also calls it "Google Auth Platform") → **Get started**: app name `Google Ads Dashboard`, your email as user support and as developer contact → **Create**. Then two tabs:
   - **Audience**: user type **External**, then **Publish app** so the status reads **In production**. Never leave it in Testing - a Testing-mode refresh token dies after 7 days (Google's number one cause of `invalid_grant`), and brand verification does not run on a Testing or Internal app.
   - **Branding**: app name, a logo, home page URL, privacy policy URL, terms of service URL, and the authorised domain - all the live site from step 0, all on the domain you own → **Save** → **Verify Branding**. Automated, a few minutes. When it passes, click **Publish branding**. If it fails, the page lists the reasons - fix them on the site and re-run.

4. **Basic access - the Keyword Planner level, in minutes.** Back on the Overview page: current level **Explorer** → **Upgrade access level** → Next: **Basic** → check the panel shows no brand-verification warning → **Apply for access**. The page says "under review, check back in a few minutes", flips to Basic, and the approval email lands at the same time. No form, no design doc, no use-case paragraph - the review is automated. Two notes:
   - One member got Basic on 15 September 2026 with the brand-verification notice still on screen. If the button is clickable, click it - but do step 3 regardless: Google's docs call verification a prerequisite, and the rejection email for unverified projects says so.
   - Rejected with "requires a successfully verified OAuth brand profile" while Branding shows verified, or Explorer rejected as "does not meet the eligibility criteria" → the billing known issue in step 1. Fix billing, wait a few minutes, apply again, or start a fresh project.
   Record "Basic, [date]" in "## My setup". **Standard access** (unlimited operations, tools other people use) is a real manual review of about 10 business days with a compliance team asking questions - nobody in this track needs it. If you ever do: `references/api-application/standard-access-response.md`.

5. **OAuth credentials.** Same project → **APIs & Services** → **Credentials** → **+ Create Credentials** → **OAuth client ID** → application type **Desktop app** → name `google-ads-cli` → **Create** → **Download JSON** → save it as `credentials.json` in the repo root (gitignored - `code/get_refresh_token.py` reads it). Paste the client ID and secret into `.env` as `GOOGLE_ADS_CLIENT_ID` and `GOOGLE_ADS_CLIENT_SECRET`. This client is what carries the access level: every call made with it gets THIS project's level, and credentials from any other project get that project's level, not this one's.

6. **Account IDs - the manager account is optional now.** The API no longer needs a manager account (MCC). `GOOGLE_ADS_CUSTOMER_ID` = the account that runs the ads, 10 digits, no dashes (top-right of Google Ads next to your avatar). If you reach that account THROUGH a manager account - `/account-setup` builds one for ownership reasons, and it is the only way to run several accounts through one set of credentials - put the manager's ID in `GOOGLE_ADS_LOGIN_CUSTOMER_ID`; otherwise leave it blank. No regular Ads account yet? Create it now at ads.google.com, and read these three lines BEFORE clicking through the signup - Google won't warn you:
   - **Time zone and currency are PERMANENT.** Google shows the dropdowns and never says they can't be changed. Pick the time zone the business actually operates in and the currency it wants to be billed in - the only fix later is a brand new account.
   - **Skip the Smart campaign.** The signup flow pushes a budget and a campaign before anything is built. Use the small "Switch to Expert Mode" / "Create an account without a campaign" link at the bottom. `/campaign-plan` builds the real campaigns later.
   - **Your own email owns the account** - never an agency's. Turn on 2-step verification and add a passkey at g.co/passkeys now - both are required before the refresh token in step 7 can be minted, and a new passkey can take days to trust.

7. **Refresh token.** Install or upgrade the library first: `pip install --upgrade "google-ads>=32" python-dotenv google-auth-oauthlib` - 32.0.0 (9 September 2026) is the first version that calls the API without a developer token, and on anything older the scripts stop with an upgrade message. Python 3.10 or newer (3.9 loses access at the v22 sunset, October 2026). Run `python3 code/get_refresh_token.py` (it reads `credentials.json`), sign in with the Google account that has Admin or Standard access to the Ads account (or to the manager, if you go through one), complete the passkey prompt, click **Allow** through the "Google hasn't verified this app" warning, and paste the printed token into `.env` as `GOOGLE_ADS_REFRESH_TOKEN`.

8. **Verify:** `python3 code/test_connection.py`. Green = the machine layer is live on this project's access level. Any error → the error list in the reference names the fix: `CLOUD_PROJECT_NOT_APPROVED_FOR_PRODUCTION` (or `ACTION_NOT_PERMITTED` on older API versions) means the project is still at Test, go back to step 2; `AUTHORIZATION_ERROR` on a project that made API calls before 9 September 2026 is Google's known issue, start a fresh project; `invalid_grant` means Testing mode or a revoked token.

**Already had a developer token before 9 September 2026?** Nothing to redo. Google moved the token's access level onto every Cloud project that used it in the last 90 days. Open the Overview page for your project and check the level matches what API Center showed; if it does not, apply for it again from the Overview page. The token line in `.env` can stay or go - the API ignores it either way. A Basic application that was pending on 10 September was closed, not denied: reapply from the Overview page and it lands in minutes. And put an inbox you actually read on the project's IAM owner or editor list (☰ → IAM & Admin → IAM) - Google's mandatory service announcements now go there, not to the API Center contact.

Record the access level, the project name and the dates in CLAUDE.md "## My setup". Everything else - `/context-layer`, `/account-setup`, `/audit`, `/keywords` on its CSV lane - runs on Explorer while Basic lands.
